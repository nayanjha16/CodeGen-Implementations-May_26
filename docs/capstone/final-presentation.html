Slide 3 · Training & Results

LoRA version comparison

Each version is scored on the same frozen gold set (n=50). For Text2SQL and SQL2NoSQL, the model’s generated query is executed and its result set is compared to the ground-truth query’s result set — a match counts as correct (execution accuracy). For NoSQL2Doc, an LLM judge scores predicted documentation against gold on a 0–10 scale. Tasks are evaluated independently; predictions are never chained.

Desktop AI SQL Assistant

RAG schema → generate → validate SELECT → execute on PostgreSQL.

Why Cursor alone wasn’t enough

  • Custom model reaches our gateway, but prompt construction is opaque
  • No way to inject retrieved DDL before generation
  • Without schema grounding, Text2SQL guesses table/column names

What the tool adds

  • Ask in English — get executable SQL, not a blank editor
  • Schema RAG — retrieve top-K tables (+ FKs), inject only that DDL
  • Closed loop — generate → SELECT-only validate → run → results
  • Safety — blocks non-SELECT; log shows tables chosen

Watch on YouTube ↗ · NL → RAG tables → SQL → validate → PostgreSQL

Improvements & future scope

  • VS Code extension — schema RAG + Chat UI on the same /v1 gateway
  • Execute-checked agent — NL→SQL→Mongo→docs with execution gates between steps
  • Full TEND test metrics — report on the full ~1.6k split, not only gold-50
  • CI eval gate — gold-50 execution smoke before every Cloud Run deploy
  • Per-task decoding & tool tabs — tuned beams; ship SQL→NoSQL and documentation flows
  • Scale-up path — 1–2B code base + same LoRA recipe; API keys and quotas on Cloud Run

Today: Desktop tool + Cursor base URL + HF adapters  →  Next: VS Code extension  →  Then: execution-gated multi-step agent
