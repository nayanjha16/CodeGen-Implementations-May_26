1 · Problem02

The Problem Legacy Java migration and code chores are slow, and generic LLMs stop at "here is some code"

Research question

Can a 0.5B code model, parameter-efficiently fine-tuned and placed inside a verify-and-repair agent, do useful repository work that the base model cannot?

Key insight

Reliability comes from the loop, not the parameter count. Execution + judging + AST-guided repair recovers what a small model gets wrong on the first try.

Constraint we honoured

Everything must run on a laptop or free CPU Space — Apple-Silicon MPS, CUDA or CPU, no code leaving the machine.

2 · What we built03

What We Built One fine-tuned checkpoint + one agent runtime, surfaced through three interfaces

Interfaces

Gradio app (4 tabs) on a Hugging Face Space, FastAPI with 11 endpoints, and a LangGraph CLI graph.

Safety rails

Every generated file goes to a pending-writes queue — review, keep all, or undo all. Nothing is silently overwritten.

Verification

ast.parse + semantic checks + pyflakes, then sandboxed execution with a 10 s timeout.

Reproducibility

Preprocess → train → evaluate → deploy scripted end-to-end, plus a Colab notebook and a pytest suite.

Techniques that mattered

Curriculum, not one big mix

Stage 1 teaches the hard structural skill (Java semantics → Python). Stage 2 adds NL and documentation at a 4× lower learning rate so the translation ability survives.

Replay + upsampling

Java2Py data is replayed into Stage 2 and the design-pattern set is upsampled 2×, because OOP-pattern examples are rare but disproportionately useful for real repositories.

Instruction templates

Every task uses a fixed delimiter format (### Translate Java to Python: … ### Python:), so one checkpoint can be steered per task at inference without a task head.

Merge, don't stack adapters

Each stage is merged back into dense weights, so inference needs no PEFT runtime and the Space loads a plain causal LM.

How the mix is assembled

Evaluation stack — six complementary signals

Surface similarity

BLEU and BERTScore — does it read like the reference?

Code-aware similarity

CodeBLEU (n-gram + syntax + dataflow) and CodeBERTScore — is the structure right?

Execution accuracy

Does it actually run and pass tests in the Docker sandbox?

Output match

Strictest signal — identical stdout to the reference program.

5 · Learnings10

Learnings & Limitations What we would tell the next team on day one

What worked

The loop beats the parameter count

Execute → judge → AST-guided repair rescues a large share of first-attempt failures. A 0.5B model inside a verification loop is more useful than a bigger model answering once.

Curriculum > single mixed run

Specialising on Java→Python first, then broadening at a lower learning rate, preserved translation quality while adding three more tasks.

Give the fixer structure, not just stderr

Passing an AST summary alongside the traceback made repairs markedly more targeted than error text alone.

Curate over collect

Dropping SQL and unusable CoDocBench records, and generating a purpose-built OOP-pattern corpus, helped more than adding raw volume.

Honest limitations

Capacity ceiling

0.5B degrades on long files and deep multi-class logic. The 1024-token window forces file-level chunking, so cross-file reasoning is shallow.

The judge is not ground truth

A separate LLM verdict can pass plausible-but-wrong code. Only execution against real tests is trustworthy, and not every task has tests.

Latency cost

Up to 3 fix cycles means several generation + execution round trips; on free CPU hardware a full solve can take tens of seconds.

Evaluation gaps

The paired fine-tuned comparison is on a small sample, and execution accuracy of 0.40 shows correctness — not similarity — is the real remaining gap.

Narrow language coverage

Java→Python only. Sandbox isolation is a subprocess timeout locally; hard isolation exists only in the Docker evaluation path.

Where we would go next

Close the evaluation loop

Full-validation fine-tuned sweep and an agent-vs-single-shot execution-accuracy comparison, so the loop's benefit is a published number.

Train on repair, not just generation

Harvest the agent's own (broken → fixed) traces into a preference dataset and fine-tune the fixer on them.

Test-first judging

Generate unit tests before code and judge on test outcomes, replacing much of the LLM verdict with executable evidence.

Scale selectively

Keep 0.5B for bulk translation, escalate to a larger model only when the loop exhausts its retries.

Harden the sandbox

Route the interactive path through the same locked-down container used for evaluation.
