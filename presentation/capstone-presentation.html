The Problem

  • Developers routinely need to translate code across languages (e.g., Java → Python) during migrations and polyglot projects.
  • Writing Python from natural language descriptions and generating documentation from code are high-value but repetitive tasks.
  • General-purpose LLMs can generate code, but they often fail on structured translation prompts and lack task-specific alignment.
  • Large models (7B+) demand substantial GPU memory and training cost — we target a compact, efficient, and deployable solution.

Research Question

Can parameter-efficient fine-tuning of a compact code LLM achieve measurable gains on verified Java→Python translation and extend to multiple code tasks?

Our Approach

Two-stage LoRA SFT on Qwen2.5-Coder-0.5B-Instruct, evaluated on AVATAR-TC with BLEU, CodeBLEU, BERTScore, and execution accuracy.

Why Qwen2.5-Coder-0.5B-Instruct?

  • Code-specialized architecture — Pre-trained on large-scale code corpora by Alibaba; designed for programming tasks, not general chat.
  • Instruction-tuned variant — The base Qwen2.5-Coder-0.5B (non-Instruct) cannot follow translation prompts; Instruct variant is essential for SFT and evaluation.
  • Compact and resource-efficient — ~503M parameters (~988 MB merged); trains on Mac MPS (Apple Silicon) and standard cloud GPUs (e.g. Colab T4).
  • Efficient fine-tuning — LoRA trains only 8.8M / 503M params (1.75%); full fine-tuning is unnecessary and costly without dedicated high-end hardware.
  • Llama-style architecture — Well-supported LoRA target modules (q/k/v/o + gate/up/down projections) in HuggingFace PEFT/TRL ecosystem.
  • Multi-task extensibility — Single checkpoint handles Java2Py, NL2Py, Code2Doc via prompt prefixes — no separate models per task.

Was Qwen Already Trained on These Datasets?

Short Answer: No — and our fine-tuning adds significant value

Qwen2.5-Coder was pre-trained on Alibaba's large-scale general code corpora (GitHub, StackOverflow, etc.). It was not specifically trained on AVATAR-TC, MBPP, or our task-specific prompt formats.

What Qwen's Pre-training Gives Us

  • General Python syntax and programming knowledge
  • Code completion and generation ability
  • Instruction-following (Instruct variant)

What Pre-training Does NOT Give Us

  • Structured Java → Python translation with our prompt format
  • Alignment to AVATAR-TC's delexicalized → detokenized style
  • Multi-task routing via ### Translate Java to Python: prefixes
  • Strong performance on OOP-heavy competitive programming code

Stage 1 — Specialize

  • Dataset: 13,794 AVATAR-TC pairs (25% of train)
  • Epochs: 3  |  LR: 2e-4
  • LoRA r=16, α=32, dropout=0.05
  • Batch: 4 × accum 8 (effective 32)
  • Precision: bf16 on Mac MPS

Stage 2 — Generalize

  • Starts from Stage 1 merged weights
  • Epochs: 2  |  LR: 5e-5 (lower to preserve Java2Py)
  • AVATAR-TC replay: 2,000 samples
  • + MBPP, DocuMint
  • Task routing via prompt prefixes

Stack: HuggingFace Transformers + PEFT (LoRA) + TRL (SFTTrainer). Trained on Mac MPS and Google Colab T4.

Evaluation Framework

Similarity Metrics

  • BLEU — n-gram overlap with reference Python
  • CodeBLEU — n-gram + syntax AST + dataflow (code-aware)
  • BERTScore — semantic similarity (roberta-large)
  • CodeBERTScore — code-specific semantic similarity

Execution Metrics

  • Execution Accuracy — Docker sandbox pass rate on I/O test cases
  • Output Match Accuracy — stdout comparison against expected output
  • OOP Category Breakdown — per-category CodeBLEU (inheritance, interfaces, generics, patterns)

Fair Comparison Protocol

  • Same SPLIT, MAX_SAMPLES, SHUFFLE, SEED in baseline and fine-tuned notebooks
  • Identical prompt templates and detokenization pipeline
  • Baseline: pre–fine-tune Instruct model
  • Fine-tuned: merged LoRA checkpoint
  • Eval on AVATAR-TC valid split (443 samples; 10-sample quick eval shown)

Value Added — What We Built Beyond the Base Model

Technical Contributions

  • Task-specific alignment — +46% BLEU, +35% CodeBLEU on Java→Python vs zero-shot Instruct model
  • Multi-task single checkpoint — 4 tasks via prompt prefixes, no task-specific models
  • Parameter-efficient training — Full pipeline on Mac MPS / Colab T4 (no A100 required)
  • Execution-grounded evaluation — Docker sandbox with real I/O test cases, not just string similarity
  • Two-stage curriculum — Specialize then multitask without catastrophic forgetting (AVATAR replay)

Engineering & Deployment

  • End-to-end MLOps pipeline — preprocess → train → eval → deploy (HF Hub + Gradio)
  • HuggingFace Hub — Saikrishna2511/qwen-multitask
  • Live Gradio demo — Interactive browser demo
  • Colab notebook — Reproducible training + eval for mentors/reviewers
  • Pytest test suite — Automated quality checks across pipeline

Limitations

  • 0.5B model — quality varies by task complexity
  • Trained on 25% AVATAR-TC train (compute constraint)
  • Execution accuracy (40%) still has room for improvement
  • Not production-ready without further evaluation

Future Work

  • Scale to Qwen2.5-Coder-1.5B or 7B with more compute
  • FastAPI serving with RAG few-shot retrieval (FAISS + codegen embeddings)
  • Agentic approach — autonomous multi-step code synthesis with tool use and self-correction
  • RLHF / DPO on execution feedback
  • More languages beyond Java→Python
