Slide 2 · Motivation

Why this project?

Production data systems span SQL and NoSQL. Small code models are cheap to run, but zero-shot CodeGen-350M is weak on structured database tasks without task-specific adapters.

The gap

  • Spider & BIRD stop at NL→SQL — no aligned Mongo or documentation
  • Full fine-tuning is too costly on student / research hardware
  • IDEs and agents need an OpenAI-compatible deployed endpoint
  • Metrics must prove execution, not string match alone

Our approach

  • PEFT / LoRA — one frozen 350M base, three swappable adapters
  • TEND — aligned NL · SQL · Mongo · docs on the same row
  • Gold-50 benchmark — frozen spider_gold_validation.jsonl
  • Independent tasks — no chained predictions during eval
